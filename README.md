# Graph Partitioning for Network Optimization

An end-to-end machine-learning project for dividing networks into balanced partitions while reducing communication between partitions.

## What the project does

Given a graph G=(V,E), the system predicts a two-way partition of the nodes and evaluates:

- **Cut size** — edges crossing between partitions
- **Partition balance** — how evenly nodes are divided
- **Normalized cut**
- **Prediction accuracy** against generated spectral labels
- **Runtime**

## ML pipeline

```
Graph generation
      ↓
Graph/node feature extraction
      ↓
Spectral partition labels
      ↓
Train/Test graph split
      ↓
Random Forest baseline
      ↓
Graph Convolutional Network (GCN)
      ↓
Local-search refinement
      ↓
Benchmark + visualization
```

## Implemented components

### Classical algorithms
- Spectral bipartitioning using the Fiedler vector
- Greedy Kernighan-Lin-style local refinement

### Machine learning
- Random Forest node classifier
- Lightweight two-layer Graph Convolutional Network implemented directly in PyTorch
- Structural node features: degree, weighted degree, clustering coefficient, PageRank, core number, and average neighbor degree

### Evaluation
- Cut size
- Balance score
- Normalized cut
- Accuracy versus spectral-generated labels
- Runtime benchmarking

## Installation

```bash
python -m venv .venv

# Windows
.venv\\Scripts\\activate

# Linux/macOS
source .venv/bin/activate

pip install -r requirements.txt
```

## Run the original demo

```bash
python -m src.cli --nodes 40 --probability 0.12
```

## Train and benchmark the GNN

```bash
python scripts/train_gnn.py --graphs 100 --nodes 40 --probability 0.12 --epochs 60
```

The benchmark is written to:

```
outputs/benchmark.json
```

## Run tests

```bash
pytest
```

## Important research note

The first supervised labels are generated by spectral partitioning. Therefore, GNN accuracy measures how well the model learns that baseline's partitioning behavior; it does **not** by itself prove that the GNN produces an optimal partition.

The next research stage is to train against stronger optimization targets and evaluate on graph families that were not used during training.
